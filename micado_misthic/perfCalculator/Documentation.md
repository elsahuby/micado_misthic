# Documentation of the performance calculator

This document explains the organisation and main execution paths of the MICADO performance calculator. The calculator uses simulation products prepared by the preprocessing pipeline, optionally adds noise, displays the resulting ADI images and exports scientific products.

**Author:** Tristan Deseine <br>
**Creation date:** 28/09/2026 <br>
**Last update:** 29/09/2026

## Repository overview

The performance calculator is organised around the following files:

* `interface.py`: creates the Qt window, widgets and user actions. It is the main file to run.
* `interface_modules/parameters.py`: reads interface parameters, computes fluxes and builds simulation paths.
* `interface_modules/processing.py`: contains the stellar and planetary processing chains.
* `interface_modules/output.py`: creates output directories and writes FITS or contrast products.
* `interface_modules/plotting.py`: displays ADI images and contrast curves in the Qt window.
* `utils.py`: contains scientific functions shared by the interface and standalone pipelines.
* `user_func.py`: exposes optional functions that can be executed from the **Files / Tools** section.
* `simu_preprocessing/`: prepares the simulation products consumed by the interface. Its operation is described in `simu_preprocessing/Documentation_preprocessing.md`.
* `test/`: contains comparison and diagnostic scripts that are not part of the interface execution.

`InputParametersWindow` combines four specialised classes from `interface_modules/`. Each class groups methods related to one responsibility: parameters and paths, processing, output files or plotting. Together, they provide the complete behaviour of the Qt interface while preserving calls such as `self.get_parameter_values()` and `self.draw_adi_image()`.

## Input data

The current processing chain expects products previously generated by `simu_preprocessing/pipeline.py`:

* `*_ADI_sum.fits`: precomputed stellar or planetary ADI image;
* `*_PSF_sum.fits`: associated PSF result;
* `*_image_cube_mean.fits`: mean absolute cube image and `NFRAMES` metadata, required when noise is enabled;
* `*_perfect_psf.fits`: perfect PSF used for photon scaling when noise is enabled;
* `*.ini`: exposure time and zenith-distance configuration. Each simulation directory must contain a single INI file.

The selected interface parameters build a directory following this structure:

```text
base_folder/
└── No_Planet or With_Planet/
    └── coronagraph/NCPA/seeing/z/filter/
        └── [planet distance]/sampling/[observation time]
```

The declination is converted to the nearest available zenith distance (`z=20` or `z=40`). Current and legacy coronagraph directory names are both recognised.

## Interface execution

When the user clicks **Run**, `run_processing()` performs the following steps:

```text
run_processing()
├── get_parameter_values(validate=True)
├── build_input_path("No_Planet", params)
└── process_precomputed_stellar_adi_then_add_noise()
```

`get_parameter_values()` collects one consistent set of typed values. Validation requires a declination, a stellar magnitude when noise is enabled, and a delta magnitude when a planet is enabled.

The method selected by `run_processing()` is currently the precomputed-ADI chain. The historical cube-based chain remains available in `processing.py`, but is not selected by the interface.

To switch method, go to the `run_processing()` function in `processing.py` and replace the call to **`process_precomputed_stellar_adi_then_add_noise()`** by the other function (**``process_planet_adi_with_noisy_cubes``**):

```
# Process the ADI products created during preprocessing.
self.process_precomputed_stellar_adi_then_add_noise(
  path, save_root=self.save_root if params["save_adi"] else None,
  apply_noise=params["noise"], params=params,
  )
```

## Current chain: precomputed ADI, then optional noise

The interface does not calculate ADI from cubes in this chain. It loads the products created during preprocessing.

```text
process_precomputed_stellar_adi_then_add_noise()
├── initialize_processing_run()
├── get_preprocessed_adi_files()
├── read ADI_sum and PSF_sum
├── if noise is enabled
│   ├── read image_cube_mean and perfect_psf
│   ├── compute stellar flux and background emission
│   └── add_noise_after_adi()
├── convolve_adi_and_psf()
├── normalize_adi_by_psf()
├── optionally save and display the stellar result
└── process_and_reconstruct_planet()
    └── process_precomputed_planet_adi_then_add_noise()
        ├── load the preprocessed planet products
        ├── add planet noise when enabled
        ├── convolve and normalize with the stellar PSF
        └── reconstruct_adi_image()
```

Noise is added to the final two-dimensional ADI image using the saved cube mean. The original ADI and preprocessing products are not modified.

## Historical chain: noise on cubes, then ADI

This chain is retained for comparison and must be selected explicitly in the code by calling `perform_adi_with_noisy_cubes()` from `run_processing()`.

```text
perform_adi_with_noisy_cubes()
├── load image_cube, psf_cube and perfect_psf
├── scale_to_photons() and add noise to every frame
├── micado_adi()
├── normalize and optionally save the stellar result
└── process_planet_adi_with_noisy_cubes()
    ├── add photon noise to the planet cube
    ├── micado_adi()
    └── normalize and reconstruct the final image
```

This is the only branch that still requires the original image and PSF cubes.

## Display and saved products

The stellar ADI is always displayed after a successful run. If a planet is enabled, the selector can display either **ADI star** or **ADI star + planet**. The contrast button computes and displays the 5-sigma contrast curve.

When **Save ADI** is enabled, a dated run directory is created with the following structure:

```text
YYYYMMDD_HHMMSS/
├── No_Planet/
│   ├── *_adi.fits
│   └── *_psf.fits
├── With_Planet/
│   └── *_planet_adi.fits
├── Reconstructed/
│   └── *_star_planet_adi.fits
└── Contrast_Curve/
    ├── *_contrast_curve.fits
    └── *_contrast_curve.png
```

The FITS headers retain the relevant processing parameters, including wavelength, pixel scale, product type, noise stage, convolution and normalization information.

The contrast curve is saved when the button is clicked. If no run output directory exists, it is written beside the selected source simulation products.

## Running the interface

From an environment containing the project dependencies, run:

```bash
python -m micado_misthic.perfCalculator.interface
```

The simulation base folder must contain the preprocessed directory structure and the `Flux_input` and `PUPIL` resources required for flux calculations.
